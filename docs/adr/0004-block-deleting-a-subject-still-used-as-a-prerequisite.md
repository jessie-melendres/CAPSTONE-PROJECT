# Deleting a subject still named as a prerequisite is blocked, not silently allowed

`subjects.prerequisite_subject_id`'s foreign key is `nullOnDelete()`: at the schema level, deleting a subject just quietly clears that field on every subject that named it as a prerequisite. Left alone, that would let an admin delete "IT101" and have "IT102" silently become enrollable with no prerequisite check at all — a real requirement disappearing with no warning. `AcademicStructureService::deleteSubject()` now checks for dependents and rejects the delete with an explanation instead, the same as the other reference-data guards. The schema still says `nullOnDelete()` — we didn't touch the migration — but the application never lets that path execute; that mismatch is intentional, not an oversight, because changing the FK behavior itself would be a much larger, riskier schema change for the same practical effect.
